🚀 ntfy Server & ACL Topic Permissions Setup

Configure write-only publishing for NtfySMS and read-only subscription for receiver devices.

Step-by-Step Security Setup

Setting up access control lists (ACL) ensures the forwarding app can only publish OTPs, while listening apps can only receive them.

1

Deploy ntfy via Docker Compose

Create a docker-compose.yml file on your server:

version: '3.8' services: ntfy: image: binwiederhergestellt/ntfy:latest container_name: ntfy restart: unless-stopped command: - serve volumes: - ./etc-ntfy:/etc/ntfy - ./var-cache-ntfy:/var/cache/ntfy ports: - "8080:80"
2

ntfy Security Hardening (`/etc/ntfy/server.yml`)

Disable anonymous publishing, public signups, and unneeded attachments:

# /etc/ntfy/server.yml base-url: "https://ntfy.example.com" # Require authentication for all topic operations auth-file: "/var/cache/ntfy/user.db" auth-default-access: "deny-all" # Disable public signups & unneeded attachments enable-signup: false enable-login: true attachment-total-size-limit: "0" enable-metrics: false
3

Create Users for Forwarder and Listener

Create two separate user accounts on your ntfy server:

# Create publisher account for NtfySMS app ntfy user add ntfysms_publisher # Create subscriber account for your receiver phone / desktop ntfy user add ntfy_receiver
4

Grant Write-Only & Read-Only Topic Permissions

Restrict topic access so NtfySMS cannot read messages, and receivers cannot post messages:

# Grant WRITE-ONLY permission on otp-* topics to NtfySMS ntfy access ntfysms_publisher "otp-*" write-only # Grant READ-ONLY permission on otp-* topics to Receiver App ntfy access ntfy_receiver "otp-*" read-only
5

Generate Access Token & Configure NtfySMS

Generate a Bearer Token for `ntfysms_publisher` and paste it into NtfySMS:

ntfy token add ntfysms_publisher

In NtfySMS App: Go to Settings → Delivery Target Nodes → + Add Node → Choose ntfy → Enter Server URL, Topic (`otp-myfeed`), and paste the generated `tk_...` token into Access Token.

🔔 Gotify Server Setup

Deploy Gotify and generate Application Tokens (`X-Gotify-Key`) for push delivery.

Deploying Gotify & Creating Application Token

1

Run Gotify Server via Docker Compose

Create a docker-compose.yml file for Gotify:

version: '3.8' services: gotify: image: gotify/server:latest container_name: gotify restart: unless-stopped environment: - GOTIFY_SERVER_PORT=80 - GOTIFY_DATABASE_DIALECT=sqlite3 - GOTIFY_DATABASE_CONNECTION=data/gotify.db volumes: - ./gotify_data:/app/data ports: - "8081:80"
2

Generate Application Token in Gotify Web UI

Log in to Gotify Web UI (`http://192.168.1.50:8080`) → Click Apps → Click Create Application → Name: `NtfySMS` → Copy generated token (`A1b2C3d4E5f6`).

3

Configure Gotify Node in NtfySMS App

In NtfySMS App: Go to Settings → Delivery Target Nodes → + Add Node → Choose Gotify → Enter Server URL and paste the token into App Token (X-Gotify-Key).

🔍 Regex Variable Extraction & Payload Customization

Extract verification codes and format custom outgoing payloads with live preview testing.

Body Extraction Regex

Extracts digits or codes from SMS text body using capture groups.

# Default regex (finds 4-8 digit numbers): \b\d{4,8}\b # Capture group regex example: Your (?:OTP|verification code) is (\d{6})

Group 1 captures automatically map to ${code}, ${otp}, and ${group1}.

Sender Header Regex

Extracts bank codes or identifiers from SMS sender headers.

# Example sender regex: ^([A-Z]{2})-([A-Z]+)$

For sender VM-HDFCBK, ${senderGroup1} = VM, ${senderGroup2} = HDFCBK.

# Custom Payload Template: [${sender}] OTP Code: ${code} # Outgoing Payload Output: [VM-HDFCBK] OTP Code: 482910
